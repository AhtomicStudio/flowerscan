# apps/web: the FlowerScan PWA

> Not scaffolded yet. Created in **T-001**. This README describes the intended shape.

React + Vite + TypeScript + Tailwind PWA. It owns everything browser-specific: camera, workers, IndexedDB,
clipboard, share, service worker, and all UI. Domain logic lives in [`@flowerscan/core`](../../packages/core/README.md).

## Planned layout

```
src/
├── app/         shell, routes, providers, age gate, error boundary
├── features/
│   ├── scan/    viewport, reticle, mode control, shutter, scan-session store
│   ├── result/  classification hero, meter, lineage tree, tag list, package-says
│   ├── search/  manual search, "Which one?" sheet
│   ├── journal/ list, detail, rating/notes
│   └── share/   share link (Web Share / copy) + journal backup & restore (JSON)
├── platform/    camera, detectors, ocr, storage (Dexie), clipboard, share: browser adapters behind interfaces
├── workers/     detection.worker.ts, ocr.worker.ts
├── data/        loads public/data/<hash>/strains.json, builds the in-memory match index
├── ui/          design-system components (Button, Sheet, Badge, Meter, Chip, Toast…)
└── styles/      tokens.css, tailwind entry
public/data/     generated by tools/vault-build (do not edit by hand)
e2e/             Playwright specs + fake camera fixtures
```

## Rules
- Features import from `ui`, `platform`, `data`, and `@flowerscan/core`, never from another feature's internals.
- Components get data through props/hooks. No fetching inside leaf components.
- Nothing is rendered that isn't backed by data or scan input (see AGENTS.md "No filler").
- Specs: [08-ux-and-design.md](../../docs/08-ux-and-design.md), [06-scan-pipeline.md](../../docs/06-scan-pipeline.md).
